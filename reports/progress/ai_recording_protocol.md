# AI 记录协议

这份文件专门给 `Claude` 和 `Codex` 用。

目标不是解释“为什么这样记录”，而是统一两边的默认动作，避免：

- 继续把所有内容堆回 `project_progress_master.md`
- 同一批信息在多个文件里重复抄写
- 自动已经能抽到的指标还靠手工再抄一遍
- 只有专业结论，没有白话解释

## 一句话原则

先写当天发生了什么，再写有没有改变方向，最后才决定要不要补实验表、词典或中枢页。

## 默认写入顺序

### 1. 先写每日日志

默认先更新：

- `reports/progress/daily/YYYY-MM-DD.md`

适用场景：

- 今天有实质推进
- 跑了新实验
- 修了工具 / 页面 / 启动器
- 做了排查并形成明确结论
- 产出了新的脚本、网页、报告或数据结果

最低要求：

- `Why`
- `专业结论`
- `白话解释`
- `做了什么`
- `产物 / 链接`
- `下一步`

### 2. 只有“阶段判断变化”才写决策日志

更新：

- `reports/progress/decision_log.md`

只有下面情况才写：

- 研究方向变了
- 默认工作流变了
- 验收标准变了
- 比较口径变了
- 某条路线正式保留 / 放弃 / 降级

不满足这些条件时，不要为了“显得完整”硬写决策日志。

### 3. 有明确 run / 对照结果时再写实验登记表

更新：

- `reports/progress/experiment_registry.md`

写入条件：

- 新增一个 run
- 新增一组 matched pair / 单变量对照
- 新增一条值得长期回看的分析结论

每次只保留一行，优先回答：

- 改了什么
- 是否可比
- 一句话结果
- 要不要继续
- 这次实验白话上到底在问什么

### 4. 有新缩写或新指标时再补词典

更新：

- `reports/progress/glossary.md`

写入条件：

- 新名字第一次出现，而且以后大概率还会重复出现
- 指标名会反复出现在图表或结论里
- 某个英文后缀容易让人看不懂

### 5. 中枢页只在“当前状态真的变了”时更新

更新：

- `reports/project_progress_hub.md`

只有下面情况才更新：

- 当前可信判断变了
- 当前瓶颈变了
- 当前优先级变了
- 默认查阅入口变了
- 最近关键判断 / 最近实验快照需要替换

不要把当天流水直接堆进中枢页。

## 明确禁止

### 不要默认继续维护历史总档

除非用户明确要求，否则：

- 不要把新增内容优先写回 `reports/project_progress_master.md`
- 不要把新结构里的内容再复制一遍回历史总档

`project_progress_master.md` 现在主要是历史归档。

### 不要手抄自动可得指标

如果 `run_summary.json` 已经存在，并且网页会自动扫描：

- 不要再在多个文件里重复抄 `steer_rmse`
- 不要再手动维护趋势数字列表
- 只在实验登记表里保留一句白话结论和必要的 1 到 2 个关键数字

自动扫描负责“数字”，人工记录负责“理解”。

### 不要把一段内容复制到多个地方

同一个事实只保留一个主位置：

- 当天发生了什么：`daily`
- 改变方向的判断：`decision_log`
- run 对照结论：`experiment_registry`
- 缩写 / 命名解释：`glossary`
- 当前总状态：`hub`

其他地方只写一句摘要 + 链接。

## Claude / Codex 执行动作清单

每次完成一轮实质工作后，按这个顺序自检：

1. 今天是否有新进展需要写入 `daily`？
2. 这次是否改变了阶段判断，需要写 `decision_log`？
3. 这次是否产生了新实验结论，需要写 `experiment_registry`？
4. 是否引入了新的英文缩写 / 指标，需要写 `glossary`？
5. 当前状态是否真的变了，需要更新 `hub`？
6. 如果网页内容会受影响，是否重新运行：
   - `py -3 tools/build_progress_dashboard.py`

## 最小动作映射

- 普通推进：写 `daily`
- 跑完新实验：写 `daily` + `experiment_registry`
- 阶段判断变化：写 `daily` + `decision_log` + 必要时更新 `hub`
- 新术语首次稳定出现：写 `glossary`
- 网页结构或数据源变化：写 `daily` + 重新生成网页

## 推荐固定话术

如果 Claude 或 Codex 需要自我约束，可以默认按下面规则执行：

- 先补当天日志，再决定是否需要补决策 / 实验 / 词典。
- 不默认更新 `project_progress_master.md`。
- 不重复抄写 `run_summary.json` 已包含的指标。
- 每条重要记录必须带一段白话解释。

## 给 AI 的简短版

如果以后要快速提醒任一模型，直接用这段就够：

> 以后项目进度默认按新结构记录：先写 `daily`，改方向才写 `decision_log`，有 run 才写 `experiment_registry`，有新术语才写 `glossary`，`project_progress_master.md` 默认只当历史总档，不再继续堆新流水；自动能从 `run_summary.json` 抽到的指标不要手抄，人工记录重点写白话解释和判定。
