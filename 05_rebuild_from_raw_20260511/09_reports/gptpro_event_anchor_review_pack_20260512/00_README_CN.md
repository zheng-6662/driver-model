# GPTPro 事件锚点审查证据包

生成日期：2026-05-12

## 这个包是做什么的

这个压缩包用于发给 GPTPro，请它审查当前旧流程里的“事件锚点重建”和“事件候选筛选”是否合理。当前核心问题不是训练新模型，而是判断旧样本的事件锚点是否可能存在语义错位。

## 建议阅读顺序

1. 先看 `reports/stage02_event_filter_user_summary_cn.md`  
   这是最简洁的用户版说明，能快速理解目前做到哪。

2. 再看 `reports/event_candidate_filter_v0_5_cn.md`  
   这是 v0.5 自动筛选的完整中文报告。

3. 再看 `tables/event_candidate_module_summary_v0_5.csv`  
   这里能看到每个场景候选总数、建议复核数量、高置信复核数量。

4. 再看 `figures/event_candidate_filter_overview_v0_5.png`  
   这是筛选概览图。

5. 最后看 `selected_review_panels/`  
   这里按场景精选了代表性复核图。每张图中的红线是当前候选锚点，灰线如果出现是最近旧锚点，橙线如果出现是之前高置信车辆失稳点。

## 包内结构

- `reports/`：中文报告和修正说明。
- `tables/`：核心表格，包括模块汇总、高置信候选、复核图索引。
- `figures/`：筛选概览图。
- `selected_review_panels/`：从 56 张代表性复核图中按场景挑出的图。

## 需要 GPTPro 重点判断的问题

1. 当前从“继续改模型”转向“重审事件锚点和样本构建”是否合理。
2. 把事件拆成“场景设计点、显式触发点、车辆响应确认点、方向盘预测标签”四层是否正确。
3. v0.4 候选锚点重建和 v0.5 自动筛选是否有逻辑漏洞。
4. v0.6 样本清单应该如何制定纳入、排除、人工复核和降级标准。
5. 哪些场景应该先进入新锚点训练，哪些场景应该暂缓。

## 注意

这个包不包含原始数据、不包含模型 checkpoint、不包含服务器密码或连接凭据。当前所有表格和图都只是用于外部审查，不代表最终训练样本已经确定。
