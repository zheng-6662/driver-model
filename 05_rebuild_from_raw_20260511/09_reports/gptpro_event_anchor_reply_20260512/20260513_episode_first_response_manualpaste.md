# GPTPro 第二次回复归档：先判定 episode，再定锚点

来源：用户在当前对话中手动粘贴 GPTPro 回复。

归档时间：2026-05-13

## 核心判断

GPTPro 进一步指出：当前困境本质上不是“没有标签所以没法做”，而是原流程把“设计触发点”当成了事件真值，但研究真正想预测的是“车辆高横向动态/侧倾/疑似失稳后，驾驶员转向并纠正”的 episode。

因此，下一步不应继续问：

> 这个 `.aed` 触发点是不是事件？

而应改成问：

> 这段驾驶过程里，是否真的出现了“车辆动态异常 + 驾驶员方向盘响应 + 回正/纠正”的完整 episode？如果出现了，它的开始、峰值、纠正分别在什么时候？

## 新的事件定义

事件不再等同于“场景触发 -> 样本开始”，而应定义为：

> 外部/道路/车辆扰动暴露后，ego 车辆出现明显横向动态或疑似失稳，驾驶员产生显著方向盘响应，并在随后出现回正、反打或稳定化过程的片段。

也就是说，应先判定 episode 是否成立，再决定 `t0`。

## 需要保留的时间点

| 时间点 | 含义 | 是否适合作训练锚点 |
|---|---|---|
| `t_design` | 场景设计点，例如道路入口、`.aed` 触发 | 候选，不是真值 |
| `t_exposure` | 事件真正影响被试的时刻，例如目标车进入冲突区域、车辆进入低 μ 区 | 很重要，适合作因果锚点 |
| `t_dyn_onset` | ego 车辆横向动态/侧倾/失稳迹象开始 | 适合作车辆状态扰动锚点 |
| `t_dyn_peak` | 横向加速度、横摆、横滚等峰值 | 描述响应强度 |
| `t_steer_onset` | 驾驶员方向盘开始明显响应 | 不能作为主锚点，容易标签泄漏 |
| `t_steer_peak` | 方向盘峰值 | 不能作为事件锚点 |
| `t_correction` | 回正、反打、稳定化阶段 | 标签描述，不是锚点 |

## 正样本、负样本、不确定样本

触发点只是实验意图，不是事件标签。触发点发生后，应分三类：

1. 正样本：触发/暴露后确实出现车辆动态异常 + 方向盘响应 + 纠正。
2. 负样本：触发发生了，但被试没有明显响应或车辆没有失稳。
3. 不确定样本：有响应，但因果关系不清、时序混乱或像正常驾驶。

## episode 挖掘顺序

1. 先用车辆信号找疑似失稳/侧倾 episode，不先用方向盘。
2. 再用方向盘判断驾驶员是否响应并纠正。
3. 再把场景触发点贴回 episode，解释它是设计触发导致、道路导致、自然驾驶导致，还是触发无效。

## 车辆动态 episode 的候选信号

- 横向加速度；
- 横摆角速度；
- 横滚速率；
- 横向偏移或横向偏移速度；
- 车速突变；
- 制动；
- 路面附着系数 μ；
- 纵向减速度。

强候选 episode 至少应满足：

> 横向加速度、横摆角速度、横滚速率、横向偏移变化中至少两个信号在短时间内明显增强。

如果只有方向盘变了，但横向加速度、横摆、横滚都没有明显响应，则不应称为车辆失稳事件。

## 方向盘响应与纠正判断

车辆动态 episode 找出来后，再看方向盘：

方向盘响应成立的证据包括：

- `t_dyn_onset` 后 0-2 秒内方向盘角明显偏离基线；
- 方向盘角速度出现峰值；
- 方向盘变化方向与车辆横向动态或避让方向有关；
- 方向盘幅值超过该记录常规波动。

纠正成立的证据包括：

- 方向盘达到峰值后回到事件前基线；
- 方向盘角速度发生反向；
- 出现“打方向-回正”或“打方向-反打-稳定”结构；
- 横摆角速度、横向加速度、横滚速率在方向盘纠正后下降；
- 横向偏移不再继续恶化。

## 两类不同因果顺序

### P1：车辆扰动在前，驾驶员纠偏在后

典型场景：低附着、μ 突变、车辆横摆/横滚异常、车辆偏离后驾驶员反打或回正。

训练锚点可以用 `t_dyn_onset` 或 `t_exposure`。

### P2：驾驶员主动打方向，随后车辆产生侧倾/横向动态

典型场景：避让施工区、NPC 变道、连续超车、弯道转向。

训练锚点应更靠前，用 `t_exposure` 或真实冲突/侵入时刻，而不是 `t_dyn_onset`。

## 建议事件类型

v0.6 至少应区分：

1. `vehicle_disturbance_correction`：车辆扰动在前，驾驶员纠偏在后；
2. `driver_initiated_avoidance`：驾驶员主动避让，车辆横向动态随后增强；
3. `normal_curve_steering`：正常弯道转向，不算失稳；
4. `trigger_no_effect`：触发了，但没有明显事件；
5. `unclear`：人工暂缓。

## 建议最小流程

1. 全数据扫描车辆动态 episode。
2. 给每个 episode 补方向盘响应信息。
3. 把场景触发点贴回 episode。
4. 只人工复核少量关键图。
5. 先做事件样本判定器/弱标签表，再训练完整轨迹模型。

## 最关键的决策

放弃“必须找到实验设计里的正确触发点”的想法，改成：

> 先找到真实发生的“车辆动态-方向盘-纠正 episode”，再回头判断它和哪个触发/场景有关。

正样本应是：

> 真实出现高横向动态或疑似失稳，并且驾驶员有明显方向盘响应和纠正的 episode。

负样本应是：

> 触发发生了，但没有诱发明显动态异常或方向盘响应的片段。

暂缓样本应是：

> 只有方向盘、只有车身峰值、只有道路入口、或者因果顺序不清的片段。
