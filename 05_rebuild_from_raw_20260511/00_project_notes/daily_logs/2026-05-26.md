## SILAB 横向偏移与样本排除规则修正

- 为什么做：用户指出 SILAB 中横向偏移可能不是连续世界坐标位移，而是随当前道路/车道参考系切换重新计算；当车辆一半及以上进入另一条道路或车道时，软件可能立刻把当前车道/道路判定切换，导致横向偏移出现突兀跳变。因此，不能再把横向偏移跳变直接当作“坐标异常、下马路、路边恢复”的硬排除证据。
- 做了什么：把这条规则写入项目进展，作为后续样本筛选、人工复核和训练 manifest 重建的硬性注意事项。
- 当前结论：
  1. 横向偏移跳变只能作为“道路/车道参考系可能切换”的提示字段。
  2. 只有横向偏移跳变，但方向盘、横向加速度、横摆、横滚、速度、高度等车辆动态连续时，不应直接排除。
  3. 是否为路边/下马路/道路外恢复，需要结合道路坐标、道路设计、车辆高度 z、姿态、速度、制动和车辆动态共同判断。
  4. 旧版本中由横向偏移跳变触发的“坐标异常/路边/下马路”结论，后续只能作为人工复核提示，不能作为硬排除规则。
  5. 后续如使用横向偏移作为模型输入，应优先增加“道路/车道参考系切换风险”标记，或改用更连续的车辆世界坐标、横向加速度、横摆、横滚等物理信号辅助判断。
- 对当前任务的影响：
  - Goal2 严格排除规则可能误伤了一批可恢复样本，尤其是只有横向偏移跳变、但车辆动态和道路语义仍合理的样本。
  - 下一版样本规则需要把 `lat_offset_jump` 从硬排除条件降级为 `reference_switch_warning` 或 `manual_review_warning`。
  - 后续训练前建议先做“道路参考系修正后的样本恢复规则”，不要直接沿用 Goal2 的严格排除结果。
- 是否需要用户决策：需要。用户后续可继续人工查看 `manual_review_images_by_priority` 中 A/B 档样本，确认哪些横向偏移跳变属于可接受的道路/车道参考系切换。

## 道路设计文件核查后的高度异常规则修正

- 为什么做：用户指出很多被放入 `03_C2_高度姿态明显_谨慎复核` 的样本高度差只有十几厘米到二十厘米左右，这种变化不像真实下马路或上斜坡；需要查看道路设计源文件确认道路高程尺度。
- 做了什么：检查 `full_centerline_layout.csv` 以及 `curve1_Area2.cfg`、`curve2_Area2.cfg` 等道路配置文件。
- 关键发现：
  1. `full_centerline_layout.csv` 显示 `curve1` 道路 z 范围为 7 m，`curve2` 道路 z 范围为 6 m。
  2. `curve1_Area2.cfg` 直接写有 `z0/z1`：例如 `0 -> -3`、`-3 -> -7`。
  3. `curve2_Area2.cfg` 直接写有 `z0/z1`：例如 `0 -> -2`、`-2 -> -5`、`-5 -> -6`。
  4. 除 `curve1/curve2` 外，其它模块在中心线总表中的道路 z 基本为 0。
  5. 因此真实道路高程变化是米级；0.1 到 0.2 m 这种小幅变化不应直接判定为下马路、上斜坡或驶出道路。
- 规则修正：
  1. 不再把小幅高度变化作为硬排除依据。
  2. `z_residual_range < 0.20 m` 默认视为车辆姿态、悬架、采样或参考误差范围内的小幅高度变化。
  3. `0.20 m <= z_residual_range < 0.50 m` 只进入复核，不硬排除。
  4. `z_residual_range >= 0.50 m` 也不能单独排除，必须结合道路坐标、道路设计、速度、制动、横摆、横滚、方向盘和横向偏移参考系共同判断。
  5. 对 `curve1/curve2`，必须看车辆 z 相对道路设计 z 的残差，不能看原始 z_range。
