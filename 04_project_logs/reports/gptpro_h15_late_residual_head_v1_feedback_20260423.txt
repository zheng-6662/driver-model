7. late residual 诊断

`test_late_residual_metrics.json` 说明新 head 不是 dead branch，它确实在工作：

但是它对 `strong_pos` 的 selectivity 还不够强：

这里最重要的解释是：
- 问题不是 “late residual head 没有学到东西”
- 问题是 “它学到的 correction 还不够 selective”
- 它只是 mildly more active on `strong_pos`
- 它还没有形成足够强的 targeted correction，去稳定修复 rare but important 的 `strong_pos` late-tail under-amplitude

因此，当前瓶颈是 selectivity 不足，不是“没学到 late residual”。

8. 为什么当前版本不能 promotion

当前 promotion 标准可概括为：
strong_pos.tail_amp_ratio_pred_over_gt >= 0.60
strong_pos.tail_flatness_rate <= 0.60
abs_tail_last_0p5s.rmse_steer <= 0.66
rmse_steer <= 0.53
late_peak_recall >= 0.62

检查结果：

对 `best_by_loss`：
- `rmse_steer=0.4954`，通过
- `abs_tail_last_0p5s.rmse_steer=0.6284`，通过
- `late_peak_recall=0.6522`，通过
- `strong_pos.tail_amp_ratio_pred_over_gt=0.3163`，失败
- `strong_pos.tail_flatness_rate=1.0000`，失败

对 `best_by_structured`：
- `rmse_steer=0.5474`，偏弱
- `abs_tail_last_0p5s.rmse_steer=0.6868`，偏弱
- `late_peak_recall=0.6656`，通过
- `strong_pos.tail_amp_ratio_pred_over_gt=0.4904`，仍失败
- `strong_pos.tail_flatness_rate=0.5000`，通过

最终结论：
- `best_by_loss` 是平均指标好看但危险桶崩掉的 collapse solution
- `best_by_structured` 是危险桶修复一半但还没过 amplitude floor、且 fit/tail 回退过多的 partial repair
- 两个 checkpoint 都不能 promotion

因此，本次分支的正确判断是：
not a new keeper
mechanism probe only

9. 对 GPTPro 的明确修改要求

请不要把这次失败解释为 optimizer 不够、width 不够、训练轮数不够，或者普通 loss micro-sweep 还没调到位。
当前证据更像是：
late residual path 有用，但它对目标 failure bucket 的 condition selectivity 还不够强。

下一版请围绕下面五个方向修改。

9.1 增强 late residual head 的 condition selectivity

当前 head 对 `strong_pos` 只是轻微更活跃：
strong_pos_mean_abs=0.0629
non_strong_mean_abs=0.0520

这说明 selectivity 差距太小。
下一版需要让 late residual correction 更明确地集中到 `strong_pos` 或 late-tail under-amplitude 样本上。

建议方向：
- 给 late residual head 增加 condition gate
- gate 输入至少考虑已有 state / reversal / sign / coarse-fine latent 信息
- 不要默认对所有样本等强度打开 late residual path
- residual output 最好支持按样本或按时间的 selective scaling
- 优先目标不是继续单纯压低全局 RMSE，而是把 `strong_pos.tail_amp_ratio_pred_over_gt` 推高到安全区间

9.2 阻止 `best_by_loss` 再次收敛到 collapse solution

当前 `best_by_loss` 的问题非常明确：
rmse_steer=0.4954
late_peak_recall=0.6522
strong_pos.tail_amp_ratio_pred_over_gt=0.3163
strong_pos.tail_flatness_rate=1.0000

这说明当前 global loss 仍会奖励一个危险解。

下一版请考虑：
- late residual loss 是否需要对 `strong_pos` late-tail under-amplitude 样本额外加权
- selection 或 structured score 是否需要更强惩罚 `strong_pos` flatness
- 是否需要在 training loss 中显式加入 strong_pos late amplitude floor 或 anti-flatness 项
- 不要把 collapse 仅仅留到 evaluation 阶段才发现，而要在训练目标或 checkpoint selection 阶段就更早阻断它

9.3 修复 `strong_pos` 的同时保护 fit/tail

当前 `best_by_structured` 虽然更接近正确方向，但代价偏大：
rmse_steer=0.5474
abs_tail_last_0p5s.rmse_steer=0.6868

这说明不能只靠强拉 `strong_pos`，否则容易把问题做成“结构更像了，但整体拟合和尾段更差”。

下一版应争取同时满足：
rmse_steer <= 0.53
abs_tail_last_0p5s.rmse_steer <= 0.66
late_peak_recall >= 0.62
strong_pos.tail_amp_ratio_pred_over_gt >= 0.60
strong_pos.tail_flatness_rate <= 0.60

如果无法同时满足，也请明确给出 tradeoff，并明确说明哪个 checkpoint 才是 keeper candidate，哪个只是 diagnostic/control。

9.4 后续 control 只使用本次 `best_by_structured`

如果继续 late residual 方向，请把本次 control checkpoint 固定为：
