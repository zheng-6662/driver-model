# G16 路线2：先判断响应类型，再选择原型轨迹

## 1. 这轮为什么做

G15 路线1说明：直接按触发前相似度找历史事件，整体 2 秒平均 RMSE 可以变低，但主响应阶段、尾段、综合选择指标和 G11 困难样本仍然不好。这说明“历史原型本身有价值”，但模型在推理时仍然不知道该选哪种方向、幅值和响应形态。

所以 G16 路线2改成两步：

1. 用训练集真实未来轨迹生成响应类型标签，例如方向、幅值等级和响应形态。这个标签只用于训练监督和诊断。
2. 推理时只看触发前车辆/事件、连续风格和肌电等可用信息，先预测响应类型，再用预测到的类型去选择训练集平均原型，或者按概率软组合多个原型。

这轮不是最终模型，而是专门回答一个问题：**如果先判断响应类型，是否能缓解旧模型“趋势像但方向、幅值和物理意义不对”的问题。**

## 2. 公平边界

- 样本清单仍使用：`/root/autodl-tmp/data_process/02_code/final_code/model/training/protocol_allphase_control_v2_context_full2s/sample_manifest.csv`。
- train/val/test 划分沿用当前 FAIR 协议。
- 原型轨迹只从训练集构建，测试集真实轨迹不会进入原型库。
- “真实响应类型原型上限”使用了测试集真实响应类型，只作为诊断上限，不能当部署模型。
- “预测响应类型原型/软原型/残差修正”推理时只使用触发前可用信息。
- 验证集用于选择特征组、标签方式、分类器强度和残差强度；测试集只做最终汇报。

## 11. 当前结论

1. 如果真实响应类型原型明显好于预测响应类型原型，说明训练集中存在可用的响应类型原型，但当前触发前信息还不足以稳定判断类型。
2. 如果预测响应类型原型接近 E10C/E5A，并改善 G11、幅值不足或错侧，说明“先判断响应类型”值得继续做成神经网络条件化模型。
3. 如果预测响应类型原型仍然只改善普通样本、不改善困难样本，就说明瓶颈不是输出结构本身，而是推理时缺少能判断方向/幅值/形态的信息，后续应优先查事件锚点、额外上下文、生理时序或多假设选择。

## 11.1 本轮实际判断

这轮的结果不建议升级为主线。

验证集选中的可部署版本是 `G16C_预测响应类型软原型加残差`，测试集结果为：`test_rmse=0.4193`、`primary_rmse=0.4119`、`tail_rmse=0.4706`、`selection_score=0.9046`、`G11_rmse=0.8694`。它的整体 2 秒平均误差看起来低于 E5A/E10C，但主响应阶段、尾段、综合选择指标和 G11 困难样本都明显更差，因此仍然属于“均值好看但物理预测不好”的路线。

响应类型判断器本身也不够可靠。最粗的“方向+幅值”在测试集最高约 `accuracy=0.6101`、`macro_f1=0.3886`；更细的“方向+幅值+形态”测试集最高只有约 `accuracy=0.3191`、`macro_f1=0.1762`。这说明触发前车辆/事件/连续风格/肌电信息目前只能粗略判断方向和幅值，无法稳定判断反向修正、多段修正等关键形态。

更重要的是，连“真实响应类型原型上限”也不好：选中上限版本 `test_rmse=0.5075`、`G11_rmse=0.7974`。这说明把同一响应类型内的训练轨迹简单平均成原型，会继续抹掉个体幅值、时序和尾段差异；问题不只是“响应类型选不准”，还包括“类型内仍然差异很大”。

因此 G16 的有效结论是：响应类型标签有诊断价值，可以继续作为辅助监督或分组分析工具；但“先判类型，再输出类型平均原型”不适合作为最终模型。后续如果继续旧流程，应避免再做简单原型平均，转向更细的样本级条件化、多假设输出、或先回到事件锚点/输入信息是否足以区分响应类型的检查。
