# Chrome-GPT 网页协作工作流记录（2026-05-11）

## 1. 记录目的

本记录说明 Codex 已验证可以通过本机 Google Chrome 操作网页版 ChatGPT，并在用户明确授权后完成两类任务：

1. 读取 Chrome 中已有 ChatGPT 项目的当前对话和完整聊天记录。
2. 在指定 ChatGPT 项目下新建聊天，输入问题，发送，并把网页 GPT 的回复带回当前 Codex 对话。

这是一条协作工作流记录，不是模型实验结果，不写入 `experiment_registry.md`。

## 2. 使用前提

- Chrome 已运行。
- Codex Chrome Extension 已安装并启用。
- Codex 与 Chrome Extension 的 native host 通信已可用。
- 用户明确要求 Codex 查看或操作 Chrome 页面。

本次验证前曾出现一次连接问题：Chrome 和扩展存在，但 native host 注册信息缺失，导致 Codex 不能和 Chrome 通信。重新修复/重试后，`openTabs()` 已能列出 Chrome 标签页，说明链路恢复。

## 3. 浏览已有 ChatGPT 对话的操作过程

本次读取目标是 Chrome 中的 ChatGPT 项目页：

- 页面标题：`3号使用者 - 研究路线与证据审查`
- 页面 URL：`https://chatgpt.com/g/g-p-69fd49769118819197fdd52929eeb6bb/c/6a01ace8-79a0-83ea-b23c-83044a8a3bfd`

实际操作步骤如下：

1. 通过 Codex Chrome 插件连接 Chrome。
2. 调用浏览器标签页列表，读取当前打开标签页的标题和 URL。
3. 从标签页列表中定位 `chatgpt.com` 且属于 `3号使用者` 项目的对话页。
4. 认领该用户标签页，使其成为 Codex 可控的浏览器标签。
5. 先做只读检查：读取页面标题、URL、输入框数量和当前可见 DOM 文本。
6. 用 `main` 区域文本作为主要读取对象；如果失败，再回退到 `body` 文本。
7. 为读取完整问答，从页面顶部开始滚动到底部，多次抓取 `main.innerText` 快照，并用文本稳定性判断是否已经到底。
8. 最后保留该标签页为 handoff 状态，避免关闭用户原本打开的页面。

本次完整读取结果：

- 抽取文本长度约 `44,654` 字符。
- 抽取到约 `1,754` 个非空文本行。
- 当前 ChatGPT DOM 中 `article` 选择器没有返回消息块，因此可靠读取方式是 `main.innerText` + 滚动快照。
- 页面中实际包含前后两段相关问答：
  - 第一段：GPT 在未确认读取证据包时给出偏保守的方法论审查。
  - 第二段：在证据包/附件信息出现后，GPT 给出带 E1/E2/E5A/E10C/G13/G14/E18/E19 等数值的完整审查。

## 4. 新建项目聊天并发送测试消息的操作过程

用户要求测试能否在 `3号使用者` 项目下新建一个新聊天，并发送一条简单消息 `你好`。

实际操作步骤如下：

1. 重新连接 Chrome，并命名本轮浏览器自动化会话。
2. 新建一个 Chrome 标签页。
3. 打开项目根地址：
   - `https://chatgpt.com/g/g-p-69fd49769118819197fdd52929eeb6bb`
4. 页面自动进入项目聊天入口：
   - `https://chatgpt.com/g/g-p-69fd49769118819197fdd52929eeb6bb/project`
5. 在页面中定位最后一个 `role=textbox` 输入框。
6. 点击输入框并填入：
   - `你好`
7. 优先查找发送按钮：
   - `button` accessible name 包含 `发送` 或 `Send`
   - `[data-testid="send-button"]`
   - `button[aria-label*="发送"]`
   - `button[aria-label*="Send"]`
8. 找到可见且可用的发送按钮后点击；如按钮定位失败，则回退为在输入框中按 `Enter`。
9. 等待网页 GPT 回复完成，并读取页面末尾文本确认发送成功。
10. 保留新聊天标签页为 handoff 状态，方便后续继续接力。

  - `https://chatgpt.com/g/g-p-69fd49769118819197fdd52929eeb6bb-3hao-shi-yong-zhe/c/6a01f5b0-8138-83ea-81cd-b45a902b6869`
- 已发送用户消息：
  - `你好`

结论：Codex 可以在用户明确要求时，通过 Chrome 在指定网页版 ChatGPT 项目下新建聊天、发送问题、等待回复，并把回复内容带回当前项目协作上下文。

## 5. 后续可复用的协作方式

后续可以直接使用以下指令风格：

- `看一下 Chrome 里 3号使用者项目下这轮 GPT 回复了什么。`
- `帮我在 3号使用者项目下新建聊天，问它：...`
- `把你对当前研究路线的质疑整理成问题，发给网页版 GPT，然后把它的回答带回来。`
- `读取网页版 GPT 的完整回复，整理成项目行动清单。`

推荐默认流程：

1. 先只读连接 Chrome，确认目标标签页和 URL。
2. 如果是读取任务，只抓取页面文本，不输入、不点击发送。
3. 如果是提问任务，优先在项目根地址新建项目聊天，避免误发到普通 ChatGPT 首页。
4. 发送后等待回复稳定，再读取最后一轮回答。
5. 操作结束后保留目标标签页为 handoff，除非用户要求关闭。

## 6. 边界和安全规则

- Codex 不会在用户未要求时主动读取 Chrome 页面。
- 读取聊天记录、发送问题都必须来自用户明确指令。
- 普通提问可以直接执行；涉及删除、公开发布、付款、账号设置、隐私外传、批量发送等有影响操作时，需要再次确认。
- 不读取或复述与任务无关的密码、付款、私密身份信息。
- 如果页面需要登录、验证码、授权或人工确认，应停下并让用户处理。
- 网页 GPT 的回复只能作为外部模型意见，不能替代本项目自己的证据审计、源码检查和实验复验。

## 7. 对当前项目的意义

这条链路使 Codex 可以和网页版 GPT 项目形成可控的“问答中继”：

- Codex 负责读取本地项目文件、实验结果、日志和代码。
- 网页 GPT 可以作为外部审查/追问对象。
- Codex 再把网页 GPT 的回答带回本地项目日志、实验计划或审查报告中。

关键限制是：网页 GPT 的回答必须被项目证据链约束，不能因为它给出结论就直接改写实验判断。所有研究结论仍以本地日志、原始结果、复验指标、预测图和代码审计为准。
