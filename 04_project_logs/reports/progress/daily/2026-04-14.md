### [workflow] 进度系统升级为多页面站点 + 白话解释 + 术语词典

- 执行主体：Codex
- Why：用户反馈当前“子分类点进去还是原始 Markdown”，可读性不足；同时很多实验名、版本名和指标名偏英文缩写，导致回看进展时理解成本很高。
- 专业结论：现有进度系统已从“单页看板”升级为“主总览 + 决策中心 + 实验中心 + 日志时间线 + 术语词典”五页结构，并把 `白话解释`、`命名拆解` 与术语词典接入了源数据与展示层。
- 白话解释：现在不只是把 Markdown 换个壳显示，而是把“这个名字是什么意思、这条结论对我意味着什么”直接写进页面里，你以后点进去子页面时不需要先自己翻译英文后缀再理解结论。
- 做了什么：
  - 重写 `tools/build_progress_dashboard.py`，让它生成多页面静态站点，而不是只生成一个总览页。
  - 新增 `reports/project_progress_decisions.html`、`reports/project_progress_experiments.html`、`reports/project_progress_daily.html`、`reports/project_progress_glossary.html`。
  - 新增 `reports/project_progress_site.css`，统一站点视觉。
  - 新建 `reports/progress/glossary.md`，专门解释项目里常见英文命名、指标和 protocol 词。
  - 给 `decision_log.md` 增加 `白话解释` 列。
  - 给 `experiment_registry.md` 增加 `命名拆解` 和 `白话解释` 列。
  - 更新记录规则和模板，要求后续记录默认补充白话解释与术语说明。
- 发现：真正影响你查阅效率的，不只是“有没有索引”，而是“名字能不能立刻看懂、结论有没有翻译成人话、子页是不是仍然原始文档”。
- 涉及术语 / 命名拆解：
  - `TF0` = `teacher_forcing_ratio = 0.0`
  - `noresid` = 关闭 residual 支路
  - `pca_latent` = PCA 低维 teacher-state 表示
  - `protocol-safe` = 满足当前 protocol 的可信口径
- 产物 / 链接：
  - `reports/project_progress_dashboard.html`
  - `reports/project_progress_decisions.html`
  - `reports/project_progress_experiments.html`
  - `reports/project_progress_daily.html`
  - `reports/project_progress_glossary.html`
  - `reports/project_progress_site.css`
  - `reports/progress/glossary.md`
