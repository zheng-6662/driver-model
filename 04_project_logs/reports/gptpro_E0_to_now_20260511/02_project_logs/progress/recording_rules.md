# 项目进度记录规则

这套规则的目标只有两个：

1. 让你查阅时先看到结论，不先看到流水账。
2. 让 Claude / Codex 追加记录时不再重复抄写同一批信息。

如果你想看更偏执行口径、可以直接给 `Claude / Codex` 使用的版本，请优先看：

- `reports/progress/ai_recording_protocol.md`

## 四层结构

### 1. 中枢页

文件：`reports/project_progress_hub.md`

只放这些内容：

- 当前研究主线
- 当前可信判断
- 当前瓶颈
- 当前优先级
- 最近关键决策
- 最近实验快照

什么时候更新：

- 阶段判断变了
- 当前主目标变了
- 当前瓶颈变了
- 默认查阅入口变了

### 2. 每日日志

目录：`reports/progress/daily/`

适合记录：

- 当天做了什么
- 为什么做
- 找到了什么
- 白话上到底意味着什么
- 产出了哪些文件 / run / 结论
- 下一步是什么

适合的写法：

- 短块追加
- 一条记录只讲一件事
- 如果已有长报告，只写一句摘要 + 链接

### 3. 决策日志

文件：`reports/progress/decision_log.md`

只有在下面情况才写：

- 研究方向变了
- 比较口径变了
- 验收标准变了
- 默认工作流变了
- 某条路线正式被保留 / 放弃 / 降级

### 4. 实验登记表

文件：`reports/progress/experiment_registry.md`

每个 run 只保留一行，专门回答：

- 改了什么
- 是否可比
- 一句话结果
- 要不要继续
- 用白话说这次实验到底在问什么

## 白话解释规则

- 新增决策默认同时写一条 `白话解释`。
- 新增实验默认同时写 `命名拆解` 和 `白话解释`。
- 如果某条记录里第一次出现一个陌生缩写、版本名或后缀，优先补进 `reports/progress/glossary.md`。
- 白话解释不要求完全口语化，但必须让“不熟悉这条线的人”也能看懂 70% 以上。
- 一句专业判断后，最好紧跟一句“所以对我来说意味着什么”。

## 去冗余规则

- 同一个事实只保留一个“主位置”。
- 中枢页只保留一句结论，不贴长过程。
- 每日日志只保留当天摘要，不复制完整实验报告。
- 实验登记表只放表格式摘要，不复制分析正文。
- 如果已经有独立报告，其他地方统一只链接，不再重写一遍。
- 但在首次出现的重要决策 / 实验里，保留一条白话解释，不把“可读性”一起删掉。

## 推荐标签

后续每日日志建议在标题前加一个短标签，便于搜索：

- `[model]` 模型 / 训练 / 评估
- `[data]` 数据 / 标签 / 预处理
- `[infra]` 启动器 / 环境 / 工具链 / 适配器
- `[literature]` 文献 / Zotero / 写作素材
- `[workflow]` 协作方式 / 记录规则 / 工作流

## 建议动作映射

- 普通排查结束：写每日日志。
- 新实验跑完：写每日日志 + 实验登记表。
- 阶段判断发生变化：写决策日志 + 更新中枢页。
- 产出独立长报告：在每日日志里写一句摘要并挂链接。
- 新缩写、新后缀、新版本名反复出现：补术语词典。

## AI 默认动作

给 `Claude / Codex` 的最简版本可以压缩成四句：

- 先更新当天 `daily`。
- 改方向才写 `decision_log`。
- 有 run 才写 `experiment_registry`。
- 有新术语才写 `glossary`。

## 推荐的最小记录块

如果只是追加一条普通进展，用下面结构就够了：

- 执行主体：
- Why：
- 专业结论：
- 白话解释：
- 做了什么：
- 发现：
- 涉及术语 / 命名拆解：
- 产物 / 链接：
- 下一步：
