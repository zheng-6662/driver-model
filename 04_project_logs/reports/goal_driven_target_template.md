# 目标驱动任务模板

把下面内容发给 Claude / Codex 即可启动“目标驱动自治推进”模式。

## 最小版

```text
目标：<必须达到的结果>
验收：<什么结果才算完成>
红线：<绝对不能做的事>
```

## 推荐版

```text
目标：<必须达到的结果>

验收：
- <指标 / 文件 / 结果 1>
- <指标 / 文件 / 结果 2>

红线：
- 不删除任何现有文件
- 不改 <某些协议 / 路径 / 数据定义>

资源边界：
- 最多允许 <时长 / GPU / 检索范围>

优先级：
- 先保证 <稳定性 / 可复现 / 速度 / 指标>
- 先保证 <趋势相似 / 延时不要太大 / 不要反向预测>

不希望采用：
- 不要走 <某类方案>

可接受的停点：
- 如果暂时做不到，至少给出 <失败证据 / 已排除路径 / 下一步建议>

尝试预算：
- 同一个小问题最多连续尝试 3-4 次，之后切换方向
```

## 适合本项目的示例

```text
目标：把 maintained 主线改成 protocol-safe 的 subject-level fixed split，并完成正式训练与验证，确保模型对极限工况下驾驶员行为和车辆状态的预测趋势基本合理。

验收：
- 训练脚本真正使用 protocol 指定的固定 subject split
- 不改 horizon / anchor / online-only 规则
- 能完成完整训练和完整测试
- run 配置、结果与判断都写入 project_progress_master.md
- 关键预测不能表现出明显大延时、系统性大偏差或大量反向预测

红线：
- 不删除任何现有文件
- 不把历史归档目录当成 active source 去大改

资源边界：
- 如果路径和风险已经论证清楚，可以直接上完整训练，不必机械先做很小 smoke

尝试预算：
- 同一个小问题最多连续尝试 3-4 次，然后切换到其他更可能影响主目标的方向

可接受的停点：
- 如果主线无法安全改到 protocol-safe，给出阻塞原因、失败证据和最优替代路线
```
